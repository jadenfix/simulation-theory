# Identifiability Before Anthropic Bayes — reproducible paper artifact

Author: **Jaden Fix**, Tempera — `Jaden@Tempera.dev`

This directory is the source-of-truth bundle for the paper. The manuscript is a foundations/identifiability result, not a claim that reality is simulated. The individual elementary lemmas are not advertised as novel; the intended contribution is the integrated pre-Bayes audit framework and its application to simulation-style anthropic inference.

## Contents

- `paper.tex` — manuscript source with analytic proofs.
- `references.bib` — bibliography.
- `citation_provenance.json` — machine-readable verification provenance and known metadata discrepancies for the central references.
- `claims.json` — theorem-by-theorem scope, assumptions, novelty status, and nonclaims.
- `reproduce.py` — Python-standard-library exact-rational reproduction and bounded falsification suite.
- `receipt.json` — deterministic byte-for-byte output generated by `reproduce.py`, including a canonical payload hash.
- `AUDIT.md` — adversarial theorem/scope audit.
- `PEER_REVIEW_LOOP.md` — preserved synthetic referee reports and the original review-plan ledger. These are simulated reviews, not external endorsements.
- `PEER_REVIEW_RESPONSE.md` — applied author responses, later-pass findings, production incidents, and the release checklist.
- `toolchain.txt` — generated by CI for each release candidate; records the Git commit, Python, pdfTeX, BibTeX, Poppler, and runner/kernel provenance.

The repository-level test `tests/test_paper_identifiability_before_anthropic_bayes.py` enforces the paper's scope guards, provenance coverage, exact receipt, and key finite falsification results.

## Exact reproduction

```bash
cd paper/identifiability-before-anthropic-bayes
python reproduce.py
git diff --exit-code -- receipt.json
```

The script uses `fractions.Fraction` for the finite calculations. It checks successful examples and failure boundaries, including support mismatch, rank-deficient mixture collisions, an invalid transformed prior, and bounded two- and three-state searches around the repeated-view rigidity theorem.

The finite searches are falsification aids. They do **not** replace the general analytic proofs in `paper.tex`.

The exact mathematical receipt and its canonical payload hash are intended to be byte-stable. The PDF is handled differently: CI records its release-specific SHA-256 together with the exact source commit and TeX/Python toolchain. We do not claim that PDF bytes must remain invariant across future TeX distributions, embedded timestamps, or platform changes.

## Paper-specific CI

`.github/workflows/paper-identifiability.yml` is the end-to-end release gate. On a clean GitHub runner it:

1. runs the paper-specific Python tests;
2. regenerates `receipt.json` and requires a clean Git diff;
3. installs a TeX toolchain;
4. records the Git commit plus Python/pdfTeX/BibTeX/Poppler and runner provenance in `toolchain.txt`;
5. compiles `paper.tex` through the complete BibTeX cycle;
6. fails on unresolved citations/references or overfull boxes;
7. checks PDF title/author metadata;
8. hashes the manuscript source, resolved bibliography, bibliography source, claim/provenance ledgers, reproduction code/receipt, tests, workflow, review/audit artifacts, toolchain record, and final PDF;
9. uploads the generated PDF, logs, complete paper source, tests, workflow, and release audit files as one GitHub Actions artifact.

A human visual pass remains a separate requirement because a successful LaTeX build cannot certify typography or visual semantics.

## Mathematical scope notes

The persistent-latent likelihood-ratio theorem is stated for either a discrete transcript or a family of component laws dominated by one common sigma-finite reference measure. In the dominated case its density identity is an almost-everywhere statement. `p_m(y)` denotes the corresponding probability mass or Radon--Nikodym density. This assumption is part of the displayed density-level formula, not a claim that arbitrary mutually singular families admit one global pointwise representation.

The one-view factorization proposition is pointwise: it applies whenever the transformed prior remains nonnegative. The manuscript separately constructs a genuine local continuum when the prior is interior and the channel has at least two distinct rows.

The repeated-view theorem assumes that both conditionally independent observations use the same channel `K` and share one persistent latent state. It is not a theorem for arbitrary view-specific channels. Lack of point identification also does not forbid Bayesian analysis: set-valued or robust posterior reporting remains available, but its prior and identifying restrictions must be explicit.

## Audit policy

1. Theorem proofs live in the manuscript rather than being delegated to code.
2. Code checks finite examples and boundary witnesses; no finite check is promoted into an unrestricted theorem.
3. `claims.json` distinguishes classical consequences, elementary structural lemmas, standard known-channel geometry, constructive witnesses, and the scoped gauge-orbit theorem.
4. The repeated-view theorem is explicitly **inside the declared nonnegative row-stochastic gauge orbit**, assumes the same observation channel for both views, and is not a global two-view latent-class identifiability theorem.
5. The persistent-latent likelihood-ratio ceiling has explicit domination and component-level absolute-continuity/support requirements for its displayed pointwise form. Support mismatch is tested as a negative boundary case.
6. Representation refinement is distinguished from physically creating additional measure-bearing observers.
7. The refinement-additivity theorem is elementary; it is not presented as a new mathematical discovery.
8. Point nonidentification is not equated with the impossibility of Bayesian inference; identified-set and robust-prior methods are acknowledged.
9. A DOI is not treated as sufficient bibliographic verification. `citation_provenance.json` records the publisher/primary source and any discrepancy used during the paper audit.
10. Synthetic peer review is preserved but clearly labeled synthetic. External expert review remains necessary before claiming external peer validation.
11. CI success establishes reproducibility of the declared artifact; it does not establish novelty, metaphysical truth, or external peer acceptance.

## Release checklist

A release candidate may be merged only after:

- zero unresolved **major** items in the synthetic-review response;
- paper-specific CI is green;
- the ordinary repository CI is green;
- the generated receipt is byte-identical to the tracked receipt;
- the PDF builds with resolved citations/references and no overfull boxes;
- PDF metadata, source/toolchain provenance, and release hashes are produced;
- the current PDF has received a human visual inspection;
- the PR has no unresolved review threads.

Journal/preprint submission is a separate step. It should additionally receive at least one adversarial read from an anthropic/self-locating-inference specialist and one from a finite-mixture/latent-variable-identifiability specialist.
