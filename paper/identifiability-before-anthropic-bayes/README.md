# Identifiability Before Anthropic Bayes — reproducible paper artifact

Author: **Jaden Figgs**, Tempera — `Jaden@Tempera.dev`

This directory is the source-of-truth bundle for the paper. The manuscript is a foundations/identifiability result, not a claim that reality is simulated. The individual elementary lemmas are not advertised as novel; the intended contribution is the integrated pre-Bayes audit framework and its application to simulation-style anthropic inference.

## Contents

- `paper.tex` — manuscript source with analytic proofs.
- `references.bib` — bibliography.
- `citation_provenance.json` — machine-readable verification provenance and known metadata discrepancies for the central references.
- `claims.json` — theorem-by-theorem scope, assumptions, novelty status, and nonclaims.
- `reproduce.py` — Python-standard-library exact-rational reproduction and bounded falsification suite.
- `receipt.json` — deterministic byte-for-byte output generated by `reproduce.py`, including a canonical payload hash.
- `AUDIT.md` — adversarial theorem/scope audit.
- `PEER_REVIEW_LOOP.md` — preserved synthetic referee reports, impact/feasibility decisions, author responses, and review-loop status. These are simulated reviews, not external endorsements.

The repository-level test `tests/test_paper_identifiability_before_anthropic_bayes.py` enforces the paper's scope guards, provenance coverage, exact receipt, and key finite falsification results.

## Exact reproduction

```bash
cd paper/identifiability-before-anthropic-bayes
python reproduce.py
git diff --exit-code -- receipt.json
```

The script uses `fractions.Fraction` for the finite calculations. It checks successful examples and failure boundaries, including support mismatch, rank-deficient mixture collisions, an invalid transformed prior, and bounded two- and three-state searches around the two-view rigidity theorem.

The finite searches are falsification aids. They do **not** replace the general analytic proofs in `paper.tex`.

## Paper-specific CI

`.github/workflows/paper-identifiability.yml` is the end-to-end release gate. On a clean GitHub runner it:

1. runs the paper-specific Python tests;
2. regenerates `receipt.json` and requires a clean Git diff;
3. installs a TeX toolchain;
4. compiles `paper.tex` through the complete BibTeX cycle;
5. fails on unresolved citations/references or overfull boxes;
6. checks PDF title/author metadata;
7. hashes the manuscript source, bibliography, claim/provenance ledgers, reproduction code/receipt, review/audit artifacts, and final PDF;
8. uploads the PDF and release audit files as a GitHub Actions artifact.

A human visual pass remains a separate requirement because a successful LaTeX build cannot certify typography or visual semantics.

## Audit policy

1. Theorem proofs live in the manuscript rather than being delegated to code.
2. Code checks finite examples and boundary witnesses; no finite check is promoted into an unrestricted theorem.
3. `claims.json` distinguishes classical consequences, elementary structural lemmas, standard known-channel geometry, constructive witnesses, and the scoped gauge-orbit theorem.
4. The two-view theorem is explicitly **inside the declared nonnegative row-stochastic gauge orbit** and is not a global two-view latent-class identifiability theorem.
5. The persistent-latent likelihood-ratio ceiling has an explicit component-level absolute-continuity/support requirement. Support mismatch is tested as a negative boundary case.
6. Representation refinement is distinguished from physically creating additional measure-bearing observers.
7. The refinement-additivity theorem is elementary; it is not presented as a new mathematical discovery.
8. A DOI is not treated as sufficient bibliographic verification. `citation_provenance.json` records the source and any discrepancy used during the paper audit.
9. Synthetic peer review is preserved but clearly labeled synthetic. External expert review remains necessary before claiming external peer validation.
10. CI success establishes reproducibility of the declared artifact; it does not establish novelty, metaphysical truth, or external peer acceptance.

## Release checklist

A release candidate may be merged only after:

- zero unresolved **major** items in `PEER_REVIEW_LOOP.md`;
- paper-specific CI is green;
- the ordinary repository CI is green;
- the generated receipt is byte-identical to the tracked receipt;
- the PDF builds with resolved citations/references and no overfull boxes;
- PDF metadata and release hashes are produced;
- the current PDF has received a human visual inspection;
- the PR has no unresolved review threads.

Journal/preprint submission is a separate step. It should additionally receive at least one adversarial read from an anthropic/self-locating-inference specialist and one from a finite-mixture/latent-variable-identifiability specialist.
